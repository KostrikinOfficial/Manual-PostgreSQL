## 🔬 `EXPLAIN`
### Как узнать, что PostgreSQL собирается делать?
Ответ: `EXPLAIN`

Например: `EXPLAIN SELECT * FROM users WHERE id = 100;`

PostgreSQL показывает план действий. Упрощённо: Что PostgreSQL собирается делать.

## 🐢 Sequential Scan
Допустим, PostgreSQL выбирает: `Seq Scan` - это последовательное сканирование таблицы.

Условно:

    строка 1
    ↓
    строка 2
    ↓
    строка 3
    ↓
    ...
    ↓
    строка 100000

PostgreSQL проверяет строки таблицы на соответствие условию.

Например: `SELECT * FROM users WHERE age = 18;`

При Seq Scan система может последовательно рассматривать таблицу и проверять: `age = 18?` для строк.

## ⚡ Index Scan
Если PostgreSQL считает индекс выгодным, план может содержать Index Scan

Например: `CREATE INDEX idx_users_email ON users(email);`

Запрос: `SELECT * FROM users WHERE email = 'test@example.com';`

### Важно: PostgreSQL сам выбирает
Даже если мы создали: `CREATE INDEX idx_users_age ON users(age);`

Это не означает: любой запрос WHERE age = ... → Index Scan

PostgreSQL оценивает стоимость.

Например: таблица из 20 строк. Тогда Seq Scan очень дешево.

## 🚦 `cost`
При `EXPLAIN` можно увидеть примерно такую информацию:

`Seq Scan on users  (cost=0.00..18.10 rows=5 width=...)`

`cost=...` - это оценка стоимости, которую использует планировщик.

`cost` - это не количество миллисекунд, а внутренняя относительная оценка стоимости операций.

## 📊 `rows`
В плане можно увидеть: `rows=5`, это оценка количества строк, которые планировщих может получить.

Например: `Seq Scan on users (cost=0.00..100.00 rows=10)`

Означает примерно: Планировщик ожидает получить около 10 строк.

Это оценка, а не обязательно фактическое количество.

## Пример `EXPLAIN`
Допустим: `EXPLAIN SELECT * FROM users WHERE id = 100;`

Если `id - PRIMARY KEY`, PostgreSQL может показать что-то вроде:

`Index Scan using users_pkey on users`, это означает: Используется индекс

Если запрос: `EXPLAIN SELECT * FROM users;` то индекс для поиска вообще не нужен, поэтому естественнее увидеть:

`Seq Scan on users`

## 💣 Index Scan Only
Идея: PostgreSQL может получить нужную информацию непосредственно из индекса, не обращаясь к таблице для каждой строки.

Например, если нам нужны только столбцы, которые находятся уже в индекса.

Пока достаточно знать:

`Seq Scan` → таблица,

`Index Scan` → индекс + обращение к таблице,

`Index Scan Only` → возможно получить данные из самого индекса.

## ❌ `EXPLAIN` ≠ `EXPLAIN ANALYZE`
### `EXPLAIN`
`EXPLAIN SELECT ...` показывает: Какой план PostgreSQL собирается использовать.
### `EXPLAIN ANALYZE`
`EXPLAIN ANALYZE SELECT ...` уже выполняет запрос и показывает реальные показатели выполнения.

## 🔎 Пример с индексом
Представим: `CREATE INDEX idx_users_email ON users(email);`

Проверяем: `EXPLAIN SELECT * FROM users WHERE email = 'a@example.com';`

Если увидим: `Index Scan using idx_users_email`

Можем сделать вывод, что этот план использует наш индекс.

А если: `Seq Scan on users`, то PostgreSQL выбрал последовательное сканирование.

Но не надо сразу делать вывод: Индекс плохой.

Возможно:
- Таблица маленькая
- Условие возвращает много строк
- Планировщик считает Seq Scan дешевле

## 🛠️ `EXPLAIN` как инструмент разработчика
Если приложение стало медленно выполнять: `SELECT ...`

Можно начать: `EXPLAIN SELECT ...`

И посмотреть:

    Seq Scan?
    Index Scan?
    какой индекс?
    оценка rows?
    cost?

И затем решить:
- Нужен ли индекс?
- Правильно ли он построен?
- Почему он не используется?
