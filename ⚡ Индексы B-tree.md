## ⚡ Индексы B-tree
### Создание индекса
Например: `CREATE INDEX idx_students_name ON students(name);`
### Индекс не означает автоматическое ускорение
Многие думают: Добавлю индекс на каждый столбец - база будет работать быстрее.

Нет. Индекс имеет свою стоимость.

Когда мы выполняем: `UPDATE`, `INSERT`, `DELETE`, базе может потребоваться обновить и индекс.

### То есть, индекс:

- Ускоряет некоторые чтения
- Занимает место
- Требует обслуживания при изменении

### B-tree

В PostgreSQL индекс по умолчанию часто создается с использованием: `B-tree`

### B-tree - это...
Структура данных, предназначенная для эффективного поиска и упорядоченного доступа к значениям.

Она хорошо подходит для операторов: `> < >= <= = BETWEEN`, а также для некоторых операторов сортировки.

Дерево позволяет сужать область поиска.

### Где B-tree особенно полезен
Например: `SELECT * FROM students WHERE id BETWEEN 100 AND 200;`

Или: `SELECT * FROM products WHERE price > 1000;`

Поскольку значения упорядочены, B-tree может эффективно работать с диапазоном.

### Самое важное про B-tree
- По умолчанию очень распространенный тип индекса
- Хорошо подходит для `= < <= > >= BETWEEN`
- Используется PostgreSQL для эффективного поиска
### И самое главное
Индекс - инструмент ускорения конкретных типов запросов, а не универсальная кнопка "Ускорить базу"
